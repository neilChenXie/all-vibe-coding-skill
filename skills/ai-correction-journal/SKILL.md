# AI 错题本（ai-correction-journal）

把 AI 执行过程中真实发生的错误，沉淀成两层内容：

- **规则积累**：精简、可直接复制进 `AGENTS.md` / `RULE.md` 的提示规则，遇到相同场景读这一段就不会再犯。
- **场景复现**：错误到底怎么发生的，便于后续维护错题本时判断这条规则是否还成立。

一条错题 = 一个 md 文件。错题本根目录另维护两个文件：`INDEX.md`（索引，用于检索和去重）和 `RULES.md`（只含规则积累，便于整段复制进任意 AGENTS.md）。

## 开始前：确认存储位置

1. 读本 skill 目录下的 `config.md`。不存在时，把同目录的 `config.example.md` 复制为 `config.md`（`config.md` 是本机文件，已被仓库 `.gitignore` 忽略）。
2. **首次使用**（`config.md` 中没有「错题本根目录」或为空）时：
   - 询问用户错题本存在哪里，并明确给出默认值 `~/.agents/ai-correction-journal`；用户没指定就用默认值，不要自己另挑路径；
   - 把实际路径写回 `config.md`；
   - 创建根目录以及 `INDEX.md`、`RULES.md` 骨架（模板见文末）。
3. 之后每次直接读 `config.md` 的路径，不重复询问。路径中的 `~` 展开为当前用户主目录。

初始化目录（只在目录/文件不存在时创建，已存在不要覆盖）：

```powershell
# PowerShell（Windows）
$root = "$HOME\.agents\ai-correction-journal"   # 换成 config.md 中的实际值
New-Item -ItemType Directory -Force -Path $root | Out-Null
```

```bash
# bash / zsh
root="$HOME/.agents/ai-correction-journal"      # 换成 config.md 中的实际值
mkdir -p "$root"
```

## 记录一条错题

### 时机

- 用户明确要求记录（"记到错题本"、"把这个坑记下来"）。
- 或者 AI 自己踩了错并已纠正，且这次错误值得复用：与环境相关、容易复发、有明确的避免方法。
- 纯笔误、一次性的手滑、尚未查清原因的问题不记录；不确定时先问用户。

### 收集信息

缺什么问什么，一次只问一个：

- **触发场景**：下次在什么情况下会犯同样的错
- **可能错误**：这次具体错在哪
- **避免方法**：下次按什么步骤或检查点执行
- **场景复现**：目标、实际执行的命令、报错原文、根因、正确做法
- **tags**：本次使用的工具或语言

### YAML 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `tags` | 是 | 本次使用的工具或语言，如 `[git]`、`[powershell, python]` |
| `日期` | 是 | 记录日期，`YYYY-MM-DD` |
| `运行环境` | 是 | 错误发生的操作系统与执行环境，如 `Windows 11 (26100)`、`macOS 15.2`、`WSL2 Ubuntu 24.04`、`Docker node:20` |
| `shell版本` | 是 | 执行命令所用 shell 及版本，如 `PowerShell 7.5.4`、`bash 5.2.37`、`zsh 5.9`、`cmd 10.0.26100` |

`运行环境` / `shell版本` 记录**错误实际发生那一侧**的真实环境。用户机器上出的错就记用户机器的，远端 / 容器 / CI 里出的错就记那一侧的，不要拿 AI 自身的运行环境顶替。确实探测不到就写"未知"，不要猜一个版本号。

### 文件命名与落位

- 路径：`<错题本根目录>/YYYY-MM-DD-<简述>.md`
- `日期` 用记录日期；`简述` 用中文短词、不留空格，例如 `2026-11-09-git-rebase-误删已推送提交.md`
- 同一天同一简述重名时追加序号：`-2`、`-3`
- 一条错题一个文件。相似错误不合并成一段，靠 `tags` 与 `INDEX.md` 的场景描述做关联

### 文件模板

```md
---
tags: [git]
日期: 2026-11-09
运行环境: Windows 11 (26100)
shell版本: PowerShell 7.5.4
---

## 规则积累

场景：「当用户要求 xxx」时，注意以下情况

可能错误：

避免方法：

## 场景复现
```

`规则积累` 里的内容要尽量精简，但又必须让后续的 AI 看懂：场景写成"当用户要求 … 时"，可能错误写成这次实际错的行为，避免方法写成可执行步骤（第 1 步、第 2 步），不要写成"要小心"这类空话。

`场景复现` 写具体些，建议覆盖：目标、实际执行的命令（可复制）、报错原文的关键几行、根因、正确做法。命令与报错用代码块，便于他人复现。

### 写入后必须同步

1. **INDEX.md**：新增一行，按日期倒序（最新在最上），同一天后记录的排在上面。
2. **RULES.md**：把该文件的「规则积累」原样追加到文末，并附上来源链接。
3. 两处链接都用相对路径的文件名，别用绝对路径。

只写了错题文件、忘了同步 INDEX/RULES，视为记录未完成。

## 复用：把规则注入 AGENTS.md

- 用户问"有没有踩过类似的坑"：先读 `INDEX.md` 按 `tags` 和场景描述筛，再打开命中的文件；多个候选时列给用户选。
- 用户要求"把规则补进 AGENTS.md / RULE.md"：读 `RULES.md`，按目标项目的相关 `tags` 筛选后复制。只复制「规则积累」段，保留 `场景 / 可能错误 / 避免方法` 三段结构；**不要**带 YAML frontmatter，**不要**带「场景复现」。
- 插入前一句话说明将追加哪几条规则，避免把无关规则塞进项目文件。
- 若目标文件里已有同场景规则，改为修订那一条，不要重复添加。

## 维护

- **规则失效**（工具版本升级、流程已改）：修订错题文件里的「规则积累」和「场景复现」，再同步改 `RULES.md` 对应段落与 `INDEX.md` 的场景描述，三处一起改，不能只改一处。
- **条目合并**：两条错题几乎重复时，可合并为一个文件（两条的复现要点都保留），删除多余文件并清理 `INDEX.md` / `RULES.md` 中的失效链接。删除任何文件前先向用户确认。
- **追问同一错误**：后续有新发现，补进同一个文件（新增 `### 追问xx` 段落），不新建文件。

## 模板

### INDEX.md

```md
# AI 错题本索引

> 由 ai-correction-journal 维护：一条错题一个 md 文件，本表按日期倒序（最新在上）。

| 日期 | tags | 场景 | 运行环境 / shell | 文件 |
|---|---|---|---|---|
| 2026-11-09 | git | 当用户要求清理本地提交历史时 | Windows 11 / PowerShell 7.5.4 | [2026-11-09-git-rebase-误删已推送提交.md](2026-11-09-git-rebase-误删已推送提交.md) |
```

### RULES.md

```md
# AI 错题本 · 规则积累

> 本文件只含「规则积累」，可直接整段复制到 AGENTS.md / RULE.md。按追加顺序排列，最新在下。
> 每条规则末尾的链接指向对应的场景复现文件。

## 规则：git rebase 前先确认有无已推送提交

场景：「当用户要求清理本地提交历史」时，注意以下情况

可能错误：
- rebase 前没确认远端是否已有这些提交，改写了已推送历史

避免方法：
1. 先执行 `git log origin/<branch>..HEAD --oneline`，确认待改写提交都未推送
2. 存在已推送提交时，先向用户确认再动手

来源：[2026-11-09-git-rebase-误删已推送提交.md](2026-11-09-git-rebase-误删已推送提交.md)
```

## 原则

- 只记录真实发生、且已经查清并纠正过的错误。不编造报错原文、命令输出或根因；尚未查清就标"待确认"。
- 规则要独立可用：光看「规则积累」这一段就能判断该不该遵守、怎么执行，不需要回头读场景复现。
- 场景复现保留关键证据（实际命令、报错行），但对 token、密码、内网地址、个人信息做脱敏。
- 错题本只放错误本身与规则，不放与错误无关的项目细节。
- 记录完回报三件事：新增的文件路径、`INDEX.md` 是否已更新、`RULES.md` 是否已更新。
